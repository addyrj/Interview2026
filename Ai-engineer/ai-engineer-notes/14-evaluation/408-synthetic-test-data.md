# 408. Synthetic Test Data
# हिंदी में: Synthetic Test Data

---

## 🔵 Simple Definition (English)
Synthetic test data is evaluation data generated by an LLM (or by templates) instead of collected from real users. Typically you give the LLM a document chunk and ask it to write a question that the chunk can answer, plus the reference answer. It gives you hundreds of test rows quickly, before you have real traffic.

## 🔵 सरल परिभाषा (Hindi)
Synthetic test data वह evaluation data है जो असली users से इकट्ठा करने के बजाय LLM (या templates) से बनाया जाता है। आमतौर पर LLM को एक document chunk देते हैं और कहते हैं कि ऐसा सवाल लिखो जिसका जवाब इस chunk में हो, साथ में reference answer भी। असली traffic से पहले ही सैकड़ों test rows जल्दी मिल जाती हैं।

---

## 🔴 Problem it Solves
New products have no logs. Experts have little time to write 500 questions. Synthetic generation gives a first test set and covers edge cases (typos, multi-hop, ambiguous questions) humans forget. Risk: LLM-written questions are cleaner and easier than real ones, so they must be filtered and mixed with real data.

## 🔴 यह क्यों बना? (Hindi)
नए products के पास logs नहीं होते। Experts के पास 500 सवाल लिखने का समय नहीं होता। Synthetic generation पहला test set देता है और ऐसे edge cases cover करता है जो humans भूल जाते हैं (typos, multi-hop, ambiguous)। जोखिम: LLM के सवाल असली से साफ और आसान होते हैं, इसलिए उन्हें filter करके असली data के साथ मिलाना ज़रूरी है।

---

## 🟢 How it Works — Step by Step

```
Step 1 → Sample chunks from your knowledge base (cover all sections)
Step 2 → Prompt LLM: "write a question answerable ONLY from this chunk + answer"
Step 3 → Vary question types: simple, multi-hop (2 chunks), reasoning, conditional
Step 4 → Add persona/style variation: expert, novice, typo-ridden, Hinglish
Step 5 → Filter: validate JSON, answerability check, remove duplicates
Step 6 → Human spot-check 10-20% of rows
Step 7 → Tag source="synthetic"; keep separate from real data in reports
```

Step 1 → Knowledge base से chunks sample करो (सभी sections cover हों)

## 💻 Code Example — Basic
```python
# Basic: template-based synthetic generator + variation (pure Python, offline)
import random  # reproducible choices

CHUNKS: dict[str, str] = {  # heading -> short fact
    "8507.60": "lithium-ion accumulators",
    "8517.13": "smartphones",
    "6109.10": "cotton T-shirts",
}
TEMPLATES: list[str] = [  # question styles (persona-like)
    "What is the HS code for {item}?",
    "hs code {item} pls",  # casual
    "Which heading covers {item} for import?",
]


def typo(s: str, rng: random.Random) -> str:  # inject a simple typo
    if len(s) < 6:  # too short to mutate
        return s  # unchanged
    i = rng.randrange(1, len(s) - 2)  # pick a position
    return s[:i] + s[i + 1] + s[i] + s[i + 2:]  # swap two neighbouring characters


def generate(n: int, seed: int = 1) -> list[dict[str, str]]:
    rng = random.Random(seed)  # reproducible generator
    rows: list[dict[str, str]] = []  # output rows
    for _ in range(n):  # produce n rows
        code, item = rng.choice(list(CHUNKS.items()))  # pick a fact
        q = rng.choice(TEMPLATES).format(item=item)  # fill a template
        if rng.random() < 0.3:  # 30% get a typo
            q = typo(q, rng)  # mutate
        rows.append({"question": q, "reference": code, "source": "synthetic"})  # row
    return rows  # list of dicts


for r in generate(4):  # show a few rows
    print(r)  # each row has question, reference, source
```

## 💻 Code Example — Advanced
```python
# Advanced: LLM-grounded generation with answerability filter (async, validated, deduped)
# pip install openai pydantic
import asyncio  # concurrency
import json  # parse
import logging  # logs

from openai import AsyncOpenAI, APIError, RateLimitError  # client + errors
from pydantic import BaseModel, Field, ValidationError  # validation

log = logging.getLogger("synth")  # logger
client = AsyncOpenAI()  # needs OPENAI_API_KEY
PERSONAS: list[str] = ["precise customs broker", "vague small trader", "user who makes typos", "Hinglish speaker"]


class Gen(BaseModel):  # one generated item
    question: str = Field(min_length=8)  # question
    reference: str = Field(min_length=1)  # answer grounded in chunk


async def chat_json(prompt: str, retries: int = 3) -> dict:
    for attempt in range(retries):  # retry loop
        try:
            r = await client.chat.completions.create(
                model="gpt-4o-mini", temperature=0.7,  # some creativity for variety
                response_format={"type": "json_object"},
                messages=[{"role": "user", "content": prompt}])
            return json.loads(r.choices[0].message.content)  # dict
        except RateLimitError:  # 429
            await asyncio.sleep(2 ** attempt)  # backoff
        except (APIError, json.JSONDecodeError) as exc:  # others
            log.warning("generation failed: %s", exc)  # log
    raise RuntimeError("generation failed")  # give up


async def make_row(chunk: str, persona: str) -> dict | None:
    try:
        d = await chat_json(f"Chunk:\n{chunk}\n\nWrite ONE question a {persona} would ask, answerable ONLY "
                            'from the chunk. JSON: {"question":"...","reference":"..."}')  # generate
        g = Gen(**d)  # validate
        v = await chat_json(f"Chunk:\n{chunk}\nQuestion: {g.question}\nAnswer: {g.reference}\n"
                            'Is the answer fully supported by the chunk? JSON {"ok": true|false}')  # judge
        if not v.get("ok"):  # drop unsupported rows
            return None
        return {**g.model_dump(), "persona": persona, "source": "synthetic", "chunk": chunk[:80]}  # keep
    except (RuntimeError, ValidationError) as exc:  # skip bad rows
        log.warning("row skipped: %s", exc)  # log
        return None


async def synthesize(chunks: list[str], per_chunk: int = 2) -> list[dict]:
    sem = asyncio.Semaphore(6)  # concurrency limit
    async def guarded(c: str, p: str) -> dict | None:
        async with sem:  # limit
            return await make_row(c, p)  # generate
    jobs = [guarded(c, PERSONAS[i % len(PERSONAS)]) for c in chunks for i in range(per_chunk)]  # all jobs
    rows = [r for r in await asyncio.gather(*jobs) if r]  # drop None
    uniq: dict[str, dict] = {r["question"].lower(): r for r in rows}  # dedupe by question
    return list(uniq.values())  # final rows
```

## 🟠 FastAPI Integration
```python
from fastapi import FastAPI, HTTPException  # web
from pydantic import BaseModel, Field  # validation

app = FastAPI()  # app


class SynthReq(BaseModel):  # request
    chunks: list[str] = Field(min_length=1, max_length=50)  # source chunks
    per_chunk: int = Field(2, ge=1, le=5)  # rows per chunk


@app.post("/dataset/synthesize")  # endpoint
async def synth(req: SynthReq) -> dict:
    try:
        rows = await synthesize(req.chunks, req.per_chunk)  # generate
    except Exception as exc:  # unexpected failure
        raise HTTPException(502, f"generation error: {exc}")  # upstream error
    return {"count": len(rows), "rows": rows, "note": "review before use"}  # response
```

## 🔗 LangChain / LangGraph Connection
Ragas has a `TestsetGenerator` that builds a knowledge graph from LangChain `Document`s and generates single-hop and multi-hop questions. A LangGraph pipeline can chain generate -> validate -> dedupe nodes.

```python
# Ragas testset generation (pip install ragas langchain-openai)
from langchain_openai import ChatOpenAI, OpenAIEmbeddings  # models
from ragas.embeddings import LangchainEmbeddingsWrapper  # wrapper
from ragas.llms import LangchainLLMWrapper  # wrapper
from ragas.testset import TestsetGenerator  # generator

def ragas_testset(docs, size: int = 20):
    gen = TestsetGenerator(llm=LangchainLLMWrapper(ChatOpenAI(model="gpt-4o-mini")),
                           embedding_model=LangchainEmbeddingsWrapper(OpenAIEmbeddings()))  # build
    return gen.generate_with_langchain_docs(docs, testset_size=size)  # dataset of questions
```

## ⚠️ Common Mistakes to Avoid

❌ Mistake 1: Using synthetic data as the only test set
✅ Correct: mix with real queries and report separately

```python
# Wrong
report(score(synthetic_rows))
# Right
report({"real": score(real_rows), "synthetic": score(synthetic_rows)})
```

❌ Mistake 2: No answerability filter, so unanswerable questions lower scores unfairly
✅ Correct: verify each (question, answer) against the chunk.

❌ Mistake 3: Generator model = judge model = production model (circular, optimistic)
✅ Correct: vary models, human spot-check.

## 🧠 Tricky Interview Question
**Q**: "Your RAG scores 95% on synthetic questions but 70% on real ones. Why?"

**Answer**: Synthetic questions are generated from the chunk, so they reuse its exact wording; the retriever finds them by lexical overlap (an easy lookup). Real users paraphrase, ask vaguely, combine topics, or ask things not in the KB. Fix: use persona and paraphrase prompts, generate multi-hop and out-of-scope questions, and weight real data more.

## ⚫ Interview Questions + Answers

Q1: [Easy] What is synthetic test data?
A1: Evaluation rows generated by an LLM or templates rather than collected from users.

Q2: [Easy] Main benefit?
A2: Fast, cheap coverage when real data is unavailable.

Q3: [Medium] Main risk?
A3: Rows are cleaner and easier than real queries, which inflates scores; also may contain wrong references.

Q4: [Medium] How do you improve quality?
A4: Ground in chunks, vary personas/types, add answerability and dedupe filters, and human-review a sample.

Q5: [Hard] How do you generate multi-hop questions?
A5: Link related chunks (shared entities or embedding neighbours), give the LLM both chunks and ask for a question needing both, then verify that neither chunk alone answers it.

---

## 🔷 When to Use + When Not to Use
✅ Use when:
- Cold start with no logs
- Expanding coverage for rare scenarios

❌ Avoid when:
- You have rich real data and the task is high-stakes (use synthetic only as a supplement)

## 💰 Cost Impact
Per row: generation ~500 tokens + validation ~500 tokens. 1,000 rows on gpt-4o-mini ≈ 1M tokens ≈ $0.2-$0.3. Ragas' generator makes more calls (knowledge graph building) so budget a few dollars for large corpora.
Optimise: generate in batches, use cheap model for validation, cache chunk embeddings, use the Batch API for big runs.
