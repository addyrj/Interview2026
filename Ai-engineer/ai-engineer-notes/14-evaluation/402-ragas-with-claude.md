---

## 🔵 Simple Definition (English)
"Ragas with Claude" means using an Anthropic Claude model as the judge LLM inside Ragas. Ragas does not ship an Anthropic client; you use `ChatAnthropic` from `langchain-anthropic` and wrap it with `LangchainLLMWrapper`. Embeddings still come from another provider because Anthropic has no embedding model.

## 🔵 सरल परिभाषा (Hindi)
"Ragas with Claude" का मतलब है Ragas में Anthropic Claude model को judge LLM बनाना। Ragas का अपना Anthropic client नहीं है; आप `langchain-anthropic` का `ChatAnthropic` लेकर `LangchainLLMWrapper` से wrap करते हैं। Embeddings किसी दूसरे provider से आते हैं क्योंकि Anthropic का embedding model नहीं है।

---

## 🔴 Problem it Solves
If your app generates with OpenAI and the judge is also OpenAI, scores can be biased (self-preference). Some companies also have Claude-only contracts or data policies. Using Claude as judge gives a second opinion and fits Claude-only stacks.

## 🔴 यह क्यों बना? (Hindi)
अगर app OpenAI से generate करता है और judge भी OpenAI है तो scores biased हो सकते हैं (self-preference)। कुछ कंपनियों के पास सिर्फ Claude का contract या data policy होती है। Claude judge दूसरी राय देता है और Claude-only stack में फिट होता है।

## 💻 Code Example — Basic
```python
# Basic: compare two judges' scores on the same rows (pure Python, offline)
from statistics import mean  # average helper


def pearson(a: list[float], b: list[float]) -> float:  # simple correlation
    if len(a) != len(b) or len(a) < 2:  # input validation
        raise ValueError("need two equal-length lists with >= 2 items")  # clear error
    ma, mb = mean(a), mean(b)  # means
    num = sum((x - ma) * (y - mb) for x, y in zip(a, b))  # covariance part
    den = (sum((x - ma) ** 2 for x in a) * sum((y - mb) ** 2 for y in b)) ** 0.5  # std part
    return num / den if den else 0.0  # avoid divide-by-zero


openai_scores = [0.9, 0.8, 0.4, 0.95, 0.6]  # pretend judge A
claude_scores = [0.85, 0.75, 0.5, 0.9, 0.55]  # pretend judge B
print(round(pearson(openai_scores, claude_scores), 3))  # high value = judges agree
disagree = [i for i, (x, y) in enumerate(zip(openai_scores, claude_scores)) if abs(x - y) > 0.3]
print("rows to review by human:", disagree)  # [] here
```

## 💻 Code Example — Advanced
```python
# Advanced: Claude as Ragas judge + OpenAI embeddings, with async + error handling
# pip install ragas langchain-anthropic langchain-openai
import asyncio  # async support
import logging  # logging
import os  # env vars

from langchain_anthropic import ChatAnthropic  # Claude via LangChain
from langchain_openai import OpenAIEmbeddings  # embeddings (Claude has none)
from ragas import EvaluationDataset, evaluate  # core
from ragas.embeddings import LangchainEmbeddingsWrapper  # wrapper
from ragas.llms import LangchainLLMWrapper  # wrapper
from ragas.metrics import Faithfulness, ResponseRelevancy  # metrics
from ragas.run_config import RunConfig  # retry config

log = logging.getLogger("ragas_claude")  # logger


def claude_judge(model: str) -> LangchainLLMWrapper:
    """Build a Claude judge. Pass a current model id from Anthropic's docs."""
    if not os.getenv("ANTHROPIC_API_KEY"):  # key check
        raise RuntimeError("ANTHROPIC_API_KEY missing")  # fail early
    return LangchainLLMWrapper(  # wrap
        ChatAnthropic(model=model, temperature=0, max_tokens=2048, timeout=60, max_retries=3)
    )


def score(rows: list[dict], model: str) -> dict[str, float]:
    if not os.getenv("OPENAI_API_KEY"):  # embeddings need a key
        raise RuntimeError("OPENAI_API_KEY missing for embeddings")  # clear error
    emb = LangchainEmbeddingsWrapper(OpenAIEmbeddings(model="text-embedding-3-small"))  # embeddings
    res = evaluate(EvaluationDataset.from_list(rows),
                   metrics=[Faithfulness(), ResponseRelevancy()],
                   llm=claude_judge(model), embeddings=emb,
                   run_config=RunConfig(max_workers=4, max_retries=5, timeout=120),
                   raise_exceptions=False)  # tolerate single-row failures
    df = res.to_pandas()  # per-row table
    if df.isna().any().any():  # report missing scores
        log.warning("some rows could not be scored")  # warn
    return df.select_dtypes("number").mean(skipna=True).round(3).to_dict()  # means


async def score_async(rows: list[dict], model: str) -> dict[str, float]:
    return await asyncio.to_thread(score, rows, model)  # keep event loop free
```

## 🟠 FastAPI Integration
```python
from fastapi import FastAPI, HTTPException  # web
from pydantic import BaseModel  # validation

app = FastAPI()  # app
JUDGE_MODEL = os.getenv("CLAUDE_JUDGE_MODEL", "")  # set from config, not hard-coded


class Req(BaseModel):  # request body
    rows: list[dict]  # dataset rows


@app.post("/eval/claude")  # endpoint
async def eval_claude(req: Req) -> dict:
    if not JUDGE_MODEL:  # config check
        raise HTTPException(500, "CLAUDE_JUDGE_MODEL not configured")  # server misconfig
    try:
        return {"scores": await score_async(req.rows, JUDGE_MODEL)}  # evaluate
    except RuntimeError as exc:  # missing keys
        raise HTTPException(500, str(exc))  # report
```

## 🔗 LangChain / LangGraph Connection
Because Ragas takes any LangChain chat model, switching judge = changing one class. In LangGraph you can route: generator node uses OpenAI, evaluator node uses `ChatAnthropic`.

```python
from langchain_anthropic import ChatAnthropic  # Anthropic wrapper

judge = ChatAnthropic(model="<current-claude-model-id>", temperature=0)  # set a real id
verdict = judge.invoke("Is this answer supported by the context? Reply YES or NO.")  # quick check
print(verdict.content)  # text of the reply
```

## ⚠️ Common Mistakes to Avoid

❌ Mistake 1: Expecting Anthropic embeddings
✅ Correct: use a separate embeddings provider

```python
# Wrong - Anthropic has no embeddings endpoint
emb = AnthropicEmbeddings()
# Right
emb = LangchainEmbeddingsWrapper(OpenAIEmbeddings(model="text-embedding-3-small"))
```

❌ Mistake 2: Low `max_tokens`, so the judge's JSON is cut off and the row becomes NaN
✅ Correct: `max_tokens=2048`.

❌ Mistake 3: Hard-coding an old model id.
✅ Correct: read the model id from config and check Anthropic's current model list.

## 🧠 Tricky Interview Question
**Q**: "You switched the judge from GPT to Claude and all scores dropped by 0.1. Did quality drop?"

**Answer**: No, the judge changed, not the system. Different judges have different strictness and calibration, so absolute scores are not comparable across judges. Re-baseline: run both judges on the old and new system, compare deltas and rankings. Keep the judge fixed for trend tracking.

## ⚫ Interview Questions + Answers

Q1: [Easy] How do you plug Claude into Ragas?
A1: Create `ChatAnthropic` from `langchain-anthropic` and wrap it with `LangchainLLMWrapper`.

Q2: [Easy] Why still need OpenAI (or another) embeddings?
A2: Anthropic offers no embedding model; metrics like ResponseRelevancy need embeddings.

Q3: [Medium] What is self-preference bias?
A3: LLM judges tend to rate outputs from their own model family higher; a different-family judge reduces it.

Q4: [Medium] How do you validate a judge?
A4: Score human-labelled rows, measure agreement (correlation or Cohen's kappa), and review disagreement cases.

Q5: [Hard] Design a multi-judge setup.
A5: Run two judges from different families, average their scores, flag rows with large disagreement for humans, store per-judge scores, and track agreement over time to detect judge drift.

## 🔷 When to Use + When Not to Use
✅ Use when:
- Generator is OpenAI and you want an independent judge
- Your org standardises on Anthropic

❌ Avoid when:
- You need a single provider for embeddings and judge
- Budget is tight and a cheaper judge already agrees with humans

## 💰 Cost Impact
Judge cost scales with rows x metrics x ~1.5K tokens. Smaller Claude models (Haiku class) are the economical choice for judging; larger ones for calibration. Prompt caching can reduce repeated instruction tokens for the judge prompts. Check current Anthropic pricing before budgeting.
Optimise: cheap tier by default, sample rows, cache by row hash, run big evaluations in batch/off-peak.
