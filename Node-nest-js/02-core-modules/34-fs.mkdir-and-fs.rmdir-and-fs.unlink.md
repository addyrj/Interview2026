# 34. fs.mkdir + fs.rmdir + fs.unlink
# हिंदी में: fs.mkdir + fs.rmdir + fs.unlink — Directories और Files Manage करना

---

## 🔵 Simple Definition (English)
`fs.mkdir()` creates a new directory. `fs.rmdir()` removes a directory. `fs.unlink()` deletes a single file (NOT a directory — that's a common confusion). Together they're the core operations for managing the folder/file structure on disk from Node.

## 🔵 सरल परिभाषा (Hindi)
`fs.mkdir()` नई directory बनाता है। `fs.rmdir()` directory को remove करता है। `fs.unlink()` एक single file को delete करता है (directory नहीं — यह एक common confusion है)। ये तीनों मिलकर Node से disk पर folder/file structure manage करने के core operations हैं।

---

## 🔴 Problem it Solves
Applications that generate per-user uploads, per-tenant data folders, temporary processing workspaces, or cleanup old files/exports need programmatic control over the directory tree — not just reading/writing file CONTENTS, but managing the STRUCTURE itself (creating nested folders, cleaning up after a job finishes, removing stale data). Without these APIs, Node couldn't manage its own working filesystem layout at all.

## 🔴 यह क्यों बना? (Hindi)
Per-user uploads, per-tenant data folders, temporary processing workspaces generate करने वाले या old files/exports cleanup करने वाले applications को directory tree पर programmatic control चाहिए — सिर्फ file CONTENTS पढ़ना/लिखना नहीं, बल्कि STRUCTURE खुद manage करना (nested folders बनाना, job खत्म होने पर cleanup करना, stale data हटाना)। इन APIs के बिना, Node अपनी ही working filesystem layout manage नहीं कर पाता।

---

## 🟢 How it Works — Step by Step

Step 1 → `fs.mkdir(path, options, callback)` or `await fs.promises.mkdir(path, options)` creates a directory at `path`. By default it throws `ENOENT` if parent directories don't exist, and `EEXIST` if the directory already exists.
Step 2 → Pass `{ recursive: true }` to create all missing parent directories AND silently succeed (no error) if the target already exists — the most commonly used, idempotent pattern.
Step 3 → `fs.rmdir(path, options)` removes an EMPTY directory by default — throws `ENOTEMPTY` if it contains files/subdirectories.
Step 4 → Pass `{ recursive: true }` to `fs.rmdir` (or better, use the newer `fs.rm(path, { recursive: true, force: true })`) to delete a directory AND everything inside it, like `rm -rf`.
Step 5 → `fs.unlink(path)` deletes exactly ONE file — calling it on a directory throws `EISDIR` (Error: Is a Directory). To delete files, you must `unlink` each one, or use `fs.rm` with `recursive: true` for a whole tree.
Step 6 → `fs.rm()` (added in Node 14.14+) is the modern, unified replacement that can delete both files AND directories with options `{ recursive, force }` — `force: true` suppresses errors if the path doesn't exist at all.

## 🟢 कैसे काम करता है? (Hindi)
Step 1 → `fs.mkdir(path, options, callback)` या `await fs.promises.mkdir(path, options)` `path` पर directory बनाता है। Default रूप से parent directories न होने पर `ENOENT` throw करता है, directory already exist होने पर `EEXIST`।
Step 2 → `{ recursive: true }` pass करो सभी missing parent directories बनाने के लिए AND target already exist करे तो silently succeed करने के लिए (कोई error नहीं) — सबसे common, idempotent pattern।
Step 3 → `fs.rmdir(path, options)` default रूप से एक EMPTY directory remove करता है — अगर उसमें files/subdirectories हैं तो `ENOTEMPTY` throw करता है।
Step 4 → `fs.rmdir` को `{ recursive: true }` pass करो (या better, newer `fs.rm(path, { recursive: true, force: true })` use करो) directory AND उसके अंदर सब कुछ delete करने के लिए, `rm -rf` जैसा।
Step 5 → `fs.unlink(path)` exactly एक FILE delete करता है — directory पर call करने पर `EISDIR` (Error: Is a Directory) throw करता है। Files delete करने के लिए, हर एक को `unlink` करना पड़ता है, या पूरे tree के लिए `fs.rm` को `recursive: true` के साथ use करो।
Step 6 → `fs.rm()` (Node 14.14+ में added) modern, unified replacement है जो files AND directories दोनों delete कर सकता है options `{ recursive, force }` के साथ — `force: true` path exist ही न करे तब भी errors suppress करता है।

## 🟡 Real World Example
**Zomato's delivery-partner document upload system:** When a new delivery partner registers, the service creates a dedicated folder `fs.mkdir(`./uploads/partner-${id}`, { recursive: true })` to hold their documents (license, vehicle RC, ID proof). If a partner's application is rejected and withdrawn, the service cleans up with `fs.rm(`./uploads/partner-${id}`, { recursive: true, force: true })`, removing the folder and ALL uploaded documents in one call — no orphaned files left on disk.

## 💻 Code Example — Basic

```javascript
// dirFileOps.js — basic directory and file operations
const fs = require('fs/promises');

async function main() {
  // Create a directory (and nested parents if needed)
  await fs.mkdir('./data/uploads/temp', { recursive: true });
  console.log('Directories created');

  // Create a file inside it
  await fs.writeFile('./data/uploads/temp/note.txt', 'Hello!');

  // List what's inside a directory
  const contents = await fs.readdir('./data/uploads/temp');
  console.log('Contents:', contents); // [ 'note.txt' ]

  // Delete a single file — unlink, NOT rmdir
  await fs.unlink('./data/uploads/temp/note.txt');
  console.log('File deleted');

  // Remove the now-empty directory
  await fs.rmdir('./data/uploads/temp');
  console.log('Empty directory removed');
}

main().catch(console.error);
```

## 💻 Code Example — Advanced

```javascript
// cleanupPatterns.js — production patterns for managing directory trees
const fs = require('fs/promises');
const path = require('path');

// ─── 1. Safe, idempotent directory creation ────────────────────────────────
async function ensureDir(dirPath) {
  await fs.mkdir(dirPath, { recursive: true }); // no error if already exists
}

// ─── 2. Recursive delete (like `rm -rf`) using modern fs.rm ────────────────
async function deleteTree(targetPath) {
  await fs.rm(targetPath, { recursive: true, force: true });
  // recursive: true  → delete directories and their contents
  // force: true       → don't throw if the path doesn't exist at all
}

// ─── 3. Manual recursive delete (for Node versions without fs.rm) ──────────
async function manualDeleteTree(targetPath) {
  const stats = await fs.stat(targetPath).catch(() => null);
  if (!stats) return; // already gone, nothing to do

  if (stats.isDirectory()) {
    const entries = await fs.readdir(targetPath);
    for (const entry of entries) {
      await manualDeleteTree(path.join(targetPath, entry)); // recurse into children
    }
    await fs.rmdir(targetPath); // now empty, safe to remove
  } else {
    await fs.unlink(targetPath); // it's a file, delete directly
  }
}

// ─── 4. Cleanup job: delete temp folders older than 24 hours ───────────────
async function cleanupOldTempFolders(tempRoot, maxAgeMs = 24 * 60 * 60 * 1000) {
  const entries = await fs.readdir(tempRoot, { withFileTypes: true });
  const now = Date.now();

  for (const entry of entries) {
    if (!entry.isDirectory()) continue; // only consider directories
    const fullPath = path.join(tempRoot, entry.name);
    const stats = await fs.stat(fullPath);
    const age = now - stats.mtimeMs; // how long since last modified

    if (age > maxAgeMs) {
      await deleteTree(fullPath); // stale — remove it
      console.log(`Cleaned up stale folder: ${fullPath}`);
    }
  }
}

(async () => {
  await ensureDir('./workspace/job-123/output');
  await fs.writeFile('./workspace/job-123/output/result.json', '{"ok":true}');

  await deleteTree('./workspace/job-123'); // removes folder + file inside it
  console.log('Workspace cleaned up');

  await cleanupOldTempFolders('./temp');
})();
```

## 🟠 Express.js Integration

```javascript
// server.js — per-request temp workspace creation + guaranteed cleanup
const express = require('express');
const fs = require('fs/promises');
const path = require('path');
const crypto = require('crypto');

const app = express();

app.post('/process-export', async (req, res) => {
  const jobId = crypto.randomUUID(); // unique ID per request
  const workDir = path.join(__dirname, 'temp', jobId);

  try {
    await fs.mkdir(workDir, { recursive: true }); // create isolated workspace
    await fs.writeFile(path.join(workDir, 'input.json'), JSON.stringify(req.body));

    // ... do the actual export processing here ...
    const resultPath = path.join(workDir, 'result.csv');
    await fs.writeFile(resultPath, 'id,amount\n1,500\n2,750\n'); // placeholder result

    const result = await fs.readFile(resultPath, 'utf8');
    res.type('text/csv').send(result);
  } catch (err) {
    res.status(500).json({ error: 'Export failed' });
  } finally {
    // ALWAYS clean up the temp workspace, success or failure
    await fs.rm(workDir, { recursive: true, force: true });
  }
});

app.listen(3000, () => console.log('Server running on port 3000'));
```

## ⚠️ Common Mistakes to Avoid

❌ Mistake 1: Using `fs.unlink` on a directory (or `fs.rmdir` on a file)
```javascript
// Wrong — unlink is for FILES only
await fs.unlink('./some-folder'); // throws EISDIR: illegal operation on a directory

// Right — use rmdir/rm for directories, unlink for files
await fs.rm('./some-folder', { recursive: true }); // removes a directory
await fs.unlink('./some-file.txt'); // removes a file
```

❌ Mistake 2: Forgetting `{ recursive: true }` and getting `ENOTEMPTY` or `ENOENT`
```javascript
// Wrong — fails if parent dirs don't exist, or if target dir has contents
await fs.mkdir('./a/b/c');     // ENOENT if "a" or "a/b" don't exist yet
await fs.rmdir('./a/b/c');     // ENOTEMPTY if "c" contains files

// Right — recursive: true handles both nested creation and full deletion
await fs.mkdir('./a/b/c', { recursive: true });
await fs.rm('./a/b/c', { recursive: true, force: true });
```

## 🧠 Tricky Interview Question

```javascript
const fs = require('fs/promises');

async function run() {
  await fs.mkdir('./test-dir');
  await fs.mkdir('./test-dir'); // called again, same path
}
run().catch(err => console.log(err.code));
```
Answer: Prints **`"EEXIST"`**. The SECOND `fs.mkdir('./test-dir')` call fails because the directory already exists and `{ recursive: true }` was NOT passed — without it, `mkdir` is strict and throws if the target already exists. This is a common gotcha: many engineers assume `mkdir` is naturally idempotent (safe to call repeatedly), but it's only idempotent when `{ recursive: true }` is explicitly passed — that option changes BOTH behaviors (creating missing parents AND silently succeeding if the final directory already exists).

## ⚫ Interview Questions + Answers

Q1: What's the difference between `fs.rmdir` and `fs.unlink`?
A1: `fs.rmdir()` removes a DIRECTORY (and by default, only if it's EMPTY — pass `{ recursive: true }` or use `fs.rm` to delete non-empty ones). `fs.unlink()` removes a single FILE — it cannot remove directories at all, throwing `EISDIR` if you try. They operate on fundamentally different filesystem entry types and are not interchangeable.

Q2: What does `fs.rm()` offer over the older `fs.rmdir()`/`fs.unlink()`?
A2: `fs.rm()` (added Node 14.14+) is a UNIFIED delete API that works for both files and directories in one call, with a `recursive` option for deleting directory trees (like Unix `rm -rf`) and a `force` option that suppresses errors if the target doesn't exist at all (useful for idempotent cleanup code that shouldn't fail just because something was already removed). It's now the recommended modern replacement, with `rmdir`/`unlink` still available for more fine-grained, type-specific control.

Q3: Why does `fs.mkdir({ recursive: true })` matter for both error prevention AND idempotency?
A3: Two separate problems it solves at once: (1) without it, creating `./a/b/c` fails with `ENOENT` if `a` or `a/b` don't already exist — `recursive: true` creates ALL missing intermediate directories automatically. (2) Without it, calling `mkdir` on an ALREADY-EXISTING directory throws `EEXIST` — `recursive: true` makes this a silent no-op instead, letting you call "ensure this directory exists" unconditionally without a separate existence check.

Q4: How would you safely delete an entire temporary job folder after processing, even if an error occurred mid-job?
A4: Wrap the processing logic in `try/catch/finally`, and put the cleanup call (`fs.rm(workDir, { recursive: true, force: true })`) in the `finally` block — this guarantees cleanup runs whether the job succeeded or threw an error, preventing orphaned temp folders from accumulating on disk over time regardless of failure paths.

Q5: What error code would you check to distinguish "directory not empty" from "directory doesn't exist" when calling `fs.rmdir`?
A5: `ENOTEMPTY` means the directory exists but still contains files/subdirectories (can't remove without `recursive: true`/`fs.rm`). `ENOENT` means the path doesn't exist at all. Checking `err.code` lets you branch logic appropriately — e.g., treating "already gone" (`ENOENT`) as a successful no-op in idempotent cleanup code, while treating `ENOTEMPTY` as a real problem requiring recursive deletion or manual intervention.

## 🔷 When to Use + When Not to Use
✅ Use when:
- Managing per-user/per-job folder structures (uploads, temp workspaces, exports).
- Writing cleanup jobs that remove stale temp data or processed artifacts.
- Building CLI/build tools that scaffold or tear down directory trees.

❌ Avoid when:
- Deleting user data without confirmation/soft-delete safeguards — `fs.rm({ recursive: true, force: true })` is irreversible; add safety checks (confirmation, trash/archive folder) for destructive user-facing operations.
- Managing structured application state that belongs in a database instead of loose files on disk.

## ⚡ 3-Line Summary
English: `fs.mkdir` creates directories (use `{ recursive: true }` for nested paths and idempotency), `fs.rmdir` removes empty directories, and `fs.unlink` deletes individual files — never confuse the two since directories and files need different delete calls. The modern `fs.rm(path, { recursive: true, force: true })` unifies deletion for both files and directory trees, ideal for cleanup jobs. Always clean up temp workspaces in a `finally` block to avoid orphaned files regardless of success or failure.
Hindi: `fs.mkdir` directories बनाता है (nested paths और idempotency के लिए `{ recursive: true }` use करो), `fs.rmdir` empty directories हटाता है, और `fs.unlink` individual files delete करता है — दोनों को कभी confuse मत करो क्योंकि directories और files के लिए अलग delete calls चाहिए। Modern `fs.rm(path, { recursive: true, force: true })` files और directory trees दोनों के लिए deletion unify करता है, cleanup jobs के लिए ideal। Temp workspaces को हमेशा `finally` block में cleanup करो ताकि success या failure में orphaned files न रहें।
