# 179. C++ in React Native
# हिंदी में: React Native में C++ (Cross-platform Native Code)
# Platform: Android ✅ | iOS ✅ | Both ✅

> **Expo SDK 54 (React Native 0.81) target** — check current docs — APIs change between SDKs. C++ TurboModule support is part of the New Architecture; exact file layout/templates vary by RN version. Native code is **not run** here.

---

## 🔵 Simple Definition (English)
**C++ in React Native** means writing shared native logic once in C++ and using it on both Android and iOS through **JSI** / **C++ TurboModules**. RN itself is built on C++: Hermes, Yoga, Fabric core, JSI are all C++.

## 🔵 सरल परिभाषा (Hindi)
**React Native में C++** का मतलब है shared native logic एक बार C++ में लिखना और उसे Android और iOS दोनों पर **JSI** / **C++ TurboModules** से चलाना। RN खुद C++ पर बना है: Hermes, Yoga, Fabric core, JSI सब C++ हैं।

---

## 🔴 Problem it Solves
```
❌ Same heavy algorithm written twice (Kotlin + Swift) -> double bugs
❌ JS too slow for crypto, image filters, parsing, ML pre-processing
❌ Existing C/C++ libraries (SQLite, OpenCV, libsodium) hard to reuse
✅ One C++ implementation, exposed to JS, shared by both platforms
```

## 🔴 यह क्यों बना? (Hindi)
```
❌ वही भारी algorithm दो बार (Kotlin + Swift) -> दोगुने bugs
❌ Crypto, image filters, parsing के लिए JS धीमा
❌ मौजूदा C/C++ libraries (SQLite, OpenCV, libsodium) reuse करना कठिन
✅ एक C++ implementation, JS को expose, दोनों platforms पर shared
```

---

## 🟢 How it Works — Step by Step
```
Step 1 → Write pure C++ logic (no platform APIs): src/cpp/
Step 2 → Wrap it in a C++ TurboModule class (derives from the generated spec / TurboModule)
Step 3 → Register the module via CxxTurboModule provider on both platforms
Step 4 → Android: CMakeLists.txt builds the .so and System.loadLibrary / autolinking
Step 5 → iOS: podspec includes the .cpp/.h files (compiled as C++)
Step 6 → JS calls the module through TurboModuleRegistry
Step 7 → Debug with Android Studio (LLDB) and Xcode
```

## 🟢 कैसे काम करता है? (Hindi)
```
Step 1 → Pure C++ logic लिखो (platform APIs के बिना): src/cpp/
Step 2 → उसे C++ TurboModule class में wrap करो
Step 3 → दोनों platforms पर CxxTurboModule provider से register करो
Step 4 → Android: CMakeLists.txt .so बनाता है, autolinking से load
Step 5 → iOS: podspec में .cpp/.h files जुड़ती हैं (C++ की तरह compile)
Step 6 → JS, TurboModuleRegistry से module call करता है
Step 7 → Android Studio (LLDB) और Xcode से debug करो
```

## 🟡 Real World Example
**Shopify's** `react-native-skia` and **MMKV** keep core logic in C++ so Android and iOS behave identically. For an Indian fintech like **PhonePe/Paytm**, a C++ encryption routine (e.g., AES via libsodium/OpenSSL) can be shared across both platforms and exposed to JS for fast, consistent token encryption.

## 💻 Code Example — Basic
```cpp
// cpp/fibonacci.h — pure C++ logic, no RN, no platform dependency (easy to unit-test)
#pragma once                       // include guard
#include <cstdint>                 // fixed-size integers

namespace calc {
  // returns the n-th Fibonacci number (iterative, O(n))
  inline uint64_t fib(uint32_t n) {
    if (n < 2) return n;           // fib(0)=0, fib(1)=1
    uint64_t a = 0, b = 1;         // previous two values
    for (uint32_t i = 2; i <= n; ++i) { // loop up to n
      uint64_t next = a + b;       // next value
      a = b;                       // shift window
      b = next;                    // shift window
    }
    return b;                      // result
  }
}
```
```cpp
// quick local test (compile with: g++ test.cpp -o test && ./test) — logic is plain C++
#include <iostream>
#include "fibonacci.h"
int main() {
  std::cout << calc::fib(10) << "\n";  // expected 55
  return 0;
}
```

## 💻 Code Example — Advanced
```ts
// src/NativeFib.ts — JS spec for a C++ TurboModule (name is what native registers)
import type { TurboModule } from 'react-native';
import { TurboModuleRegistry } from 'react-native';

export interface Spec extends TurboModule {
  fib(n: number): number;                     // sync call into C++
}
export default TurboModuleRegistry.getEnforcing<Spec>('NativeFib');
```
```cpp
// cpp/NativeFib.h — C++ TurboModule class (shape follows RN's C++ TurboModule template;
// base class name comes from Codegen output for your spec — check your RN version's docs)
#pragma once
#include <memory>
#include "fibonacci.h"
// NativeFibCxxSpec is generated by Codegen when the spec is in modules "all/modules" with cxx platform
#include <NativeFibSpecJSI.h>  // generated header (name = <codegenConfig.name>JSI.h)

namespace facebook::react {
class NativeFib : public NativeFibCxxSpec<NativeFib> {   // CRTP base from Codegen
 public:
  explicit NativeFib(std::shared_ptr<CallInvoker> jsInvoker) // JS thread scheduler
      : NativeFibCxxSpec(std::move(jsInvoker)) {}

  // implements spec method fib(n): runs in C++, returns double to JS
  double fib(jsi::Runtime& rt, double n) {
    if (n < 0 || n > 90) {                    // validate: fib(93) overflows uint64
      throw jsi::JSError(rt, "n must be 0..90"); // becomes JS Error
    }
    return static_cast<double>(calc::fib(static_cast<uint32_t>(n))); // call shared logic
  }
};
}
```
```json
{
  "codegenConfig": {
    "name": "NativeFibSpec",
    "type": "modules",
    "jsSrcsDir": "src",
    "android": { "javaPackageName": "com.nativefib" },
    "ios": { "modulesProvider": { "NativeFib": "NativeFib" } }
  }
}
```
```
# NOTE: "cxx" platform modules need extra registration (cxxModuleCMakeListsModulePath on Android,
# modulesProvider on iOS). Config keys differ across RN versions -> follow the official
# "C++ TurboModules" guide of your RN version.
```

## 📱 Android vs iOS Difference
| Feature | Android | iOS |
|---------|---------|-----|
| Build system | CMake (`CMakeLists.txt`) + NDK | Xcode / podspec (`.cpp` compiled as ObjC++/C++) |
| Loading | `System.loadLibrary` / autolink | Statically linked |
| Debugger | Android Studio LLDB | Xcode LLDB |
| ABIs | arm64-v8a, armeabi-v7a, x86_64 | arm64 (device), arm64/x86_64 (sim) |
| Common error | Missing NDK / ABI mismatch | Header search path / `-std=c++20` flags |

## ⚠️ Common Mistakes to Avoid
❌ Mistake 1: Platform-specific headers in shared C++
✅ Correct: Keep shared code pure C++; platform code stays in Kotlin/Swift.

❌ Mistake 2: Memory leaks / dangling references
✅ Correct: Use smart pointers (`std::shared_ptr`, `std::unique_ptr`), RAII.

❌ Mistake 3: Blocking the JS thread
✅ Correct: Long C++ work should run on a worker thread and return a Promise (resolve via `CallInvoker`).

## 🧠 Tricky Interview Question
**Q: Your C++ function works on iOS but crashes on Android with `UnsatisfiedLinkError`. What happened?**

**Answer:** The shared library (`.so`) was not built or loaded: missing `CMakeLists.txt` entry, wrong library name in `System.loadLibrary`, or unsupported ABI. iOS statically links so it does not need that step.

---

## ⚫ Interview Questions + Answers

**Q1: Why use C++ in RN?**
A1: Shared performance-critical logic across platforms, reuse of existing libs.

**Q2: What parts of RN itself are C++?**
A2: Hermes, JSI, Yoga, Fabric core, and TurboModule infrastructure.

**Q3: C++ TurboModule vs platform TurboModule?**
A3: C++ one is written once and shared; platform one is separate Kotlin/Swift code per OS.

**Q4: How to avoid blocking JS?**
A4: Offload to a thread and return a Promise using `CallInvoker`.

**Q5: Biggest risk of C++?**
A5: Memory safety bugs crash the whole app (no JS try/catch protects against segfaults).

---

## 🔷 When to Use + When Not to Use
✅ Use when:
- Crypto, image/audio processing, parsing, game logic
- Reusing mature C/C++ libraries

❌ Avoid when:
- Simple Android/iOS API wrappers (Kotlin/Swift easier)
- Team lacks C++ experience
