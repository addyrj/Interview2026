# 364. PyMongo — MongoDB
# हिंदी में: PyMongo — MongoDB का official Python driver

---

## 🔵 Simple Definition (English)
PyMongo is the official synchronous Python driver for MongoDB, a database that stores JSON-like documents instead of table rows. You insert Python dicts, query with dict filters, and the driver handles the network and BSON conversion.

## 🔵 सरल परिभाषा (Hindi)
PyMongo, MongoDB का official synchronous Python driver है। MongoDB table rows की जगह JSON जैसे documents रखता है। आप Python dicts insert करते हैं, dict filters से query करते हैं, और network व BSON conversion driver संभालता है।

---

## 🔴 Problem it Solves
Relational tables need a fixed schema, joins and migrations. Data like product catalogs, user profiles or event logs changes shape often and is naturally nested. MongoDB stores such data as flexible documents, and PyMongo lets Python talk to it with plain dicts and lists, with no SQL and no mapping layer.

## 🔴 यह क्यों बना? (Hindi)
Relational tables में fixed schema, joins और migrations चाहिए। Product catalog, user profile या event logs जैसा data अक्सर shape बदलता है और स्वभाव से nested होता है। MongoDB ऐसे data को flexible documents में रखता है, और PyMongo से Python plain dicts और lists के साथ उससे बात करता है, बिना SQL और बिना mapping layer के।

---

## 🟢 How it Works — Step by Step

```
Step 1 → client = MongoClient(uri)      one per process (has a connection pool inside)
Step 2 → db = client["shop"]; col = db["users"]    (created lazily on first write)
Step 3 → Write:  insert_one / insert_many   -> driver adds "_id" (ObjectId) if missing
Step 4 → Read:   find_one(filter, projection) / find(filter).sort().limit()  -> Cursor
Step 5 → Update: update_one(filter, {"$set": {...}}) with operators $set $inc $push
Step 6 → Delete: delete_one / delete_many;  speed up with create_index
Step 7 → aggregate([...stages]) runs a pipeline ($match, $group, $sort) on the server
```

## 🟢 कैसे काम करता है? (Hindi)
```
Step 1 → client = MongoClient(uri)      प्रति process एक (अंदर connection pool होता है)
Step 2 → db = client["shop"]; col = db["users"]    (पहले write पर अपने आप बनता है)
Step 3 → Write:  insert_one / insert_many   -> "_id" (ObjectId) न हो तो driver जोड़ देता है
Step 4 → Read:   find_one(filter, projection) / find(filter).sort().limit()  -> Cursor
Step 5 → Update: update_one(filter, {"$set": {...}}) operators $set $inc $push के साथ
Step 6 → Delete: delete_one / delete_many;  तेज़ी के लिए create_index
Step 7 → aggregate([...stages]) server पर pipeline ($match, $group, $sort) चलाता है
```

## 🟡 Real World Example
A product catalog at a Flipkart-style site stores each product as one document with nested specs and a list of images; different categories have different fields. A game backend logs events (`{user, event, ts, data}`) into a collection and uses an aggregation pipeline for daily active users. A CMS stores blog posts with comments embedded in the same document.

## 🟡 Real Example Hindi mein
Flipkart जैसी site का product catalog हर product को एक document में रखता है जिसमें nested specs और images की list होती है; अलग categories के fields अलग होते हैं। Game backend events (`{user, event, ts, data}`) को collection में log करता है और daily active users के लिए aggregation pipeline चलाता है। CMS blog posts को comments सहित एक ही document में रखता है।

## 💻 Code Example — Basic
```python
# Basic PyMongo CRUD
from pymongo import MongoClient                   # sync MongoDB client

client: MongoClient = MongoClient("mongodb://127.0.0.1:34201", serverSelectionTimeoutMS=3000)   # connect (lazy)
db = client["shop_demo"]                          # pick database (created on first write)
users = db["users"]                               # pick collection
users.drop()                                      # start clean for the demo

res = users.insert_one({"name": "Asha", "age": 25, "city": "Delhi"})   # create one document
print(type(res.inserted_id).__name__)             # ObjectId generated by the driver
users.insert_many([{"name": "Ravi", "age": 31, "city": "Pune"},
                   {"name": "Meera", "age": 28, "city": "Delhi"}])   # create many
print(users.count_documents({}))                  # total documents
print(users.find_one({"name": "Ravi"}, {"_id": 0}))   # read one, hide _id
print([d["name"] for d in users.find({"city": "Delhi"}).sort("age", -1)])   # filter + sort
r = users.update_one({"name": "Asha"}, {"$set": {"age": 26}, "$inc": {"logins": 1}})   # update operators
print(r.matched_count, r.modified_count)          # 1 1
print(users.delete_one({"name": "Meera"}).deleted_count)   # delete
print(users.find_one({"name": "Nobody"}))         # no match -> None, not an error
client.close()                                    # release sockets

# Output:
# ObjectId
# 3
# {'name': 'Ravi', 'age': 31, 'city': 'Pune'}
# ['Meera', 'Asha']
# 1 1
# 1
# None
```

## 💻 Code Example — Advanced
```python
# Production style: repository class, unique index, aggregation, error handling
from typing import Any                            # type hint for documents
from pymongo import MongoClient, ASCENDING        # client and index direction
from pymongo.collection import Collection         # type for collection
from pymongo.errors import DuplicateKeyError, ServerSelectionTimeoutError   # driver errors


class UserRepo:
    """Small data-access layer over the users collection."""

    def __init__(self, col: Collection) -> None:
        self.col: Collection = col                # store the collection
        self.col.create_index([("email", ASCENDING)], unique=True)   # unique email, idempotent

    def create(self, name: str, email: str, city: str) -> str:
        try:                                      # unique index may reject
            return str(self.col.insert_one({"name": name, "email": email, "city": city}).inserted_id)
        except DuplicateKeyError as e:            # email already exists
            raise ValueError(f"email {email} already registered") from e   # domain error

    def by_city(self) -> list[dict[str, Any]]:
        pipeline: list[dict[str, Any]] = [        # aggregation pipeline
            {"$group": {"_id": "$city", "users": {"$sum": 1}}},   # count users per city
            {"$sort": {"users": -1, "_id": 1}},   # biggest city first
        ]
        return list(self.col.aggregate(pipeline)) # run on the server


client: MongoClient = MongoClient("mongodb://127.0.0.1:34201", serverSelectionTimeoutMS=3000)   # connect
col: Collection = client["shop_demo"]["users_prod"]   # collection
col.drop()                                        # clean demo state
repo = UserRepo(col)                              # build repo
repo.create("Asha", "asha@x.com", "Delhi")        # insert
repo.create("Ravi", "ravi@x.com", "Pune")         # insert
repo.create("Meera", "meera@x.com", "Delhi")      # insert
print(repo.by_city())                             # grouped result
try:                                              # duplicate handling
    repo.create("Asha2", "asha@x.com", "Delhi")   # same email
except ValueError as e:                           # caught
    print("Error:", e)                            # message
try:                                              # server down handling
    bad = MongoClient("mongodb://127.0.0.1:1", serverSelectionTimeoutMS=300)   # nothing listens
    bad.admin.command("ping")                     # forces a connection attempt
except ServerSelectionTimeoutError:               # driver gives up after timeout
    print("Error: MongoDB unreachable")           # friendly message
client.close()                                    # cleanup

# Output (server running on a local test port):
# [{'_id': 'Delhi', 'users': 2}, {'_id': 'Pune', 'users': 1}]
# Error: email asha@x.com already registered
# Error: MongoDB unreachable
```

## 🟠 JavaScript vs Python Comparison

| Concept | Python (PyMongo) | JavaScript (Node driver) |
|---------|------------------|-------------------------|
| Connect | `MongoClient(uri)` | `new MongoClient(uri); await client.connect()` |
| Insert | `col.insert_one({...})` | `await col.insertOne({...})` |
| Query | `col.find({"age": {"$gt": 18}})` | `col.find({age: {$gt: 18}}).toArray()` |
| Cursor to list | `list(cursor)` | `await cursor.toArray()` |
| Async | PyMongo sync; Motor / PyMongo Async API | native Promises |

```python
# Python way — sync call returns data directly
from pymongo import MongoClient                    # driver
col = MongoClient("mongodb://127.0.0.1:34201")["shop_demo"]["js_cmp"]   # collection
col.insert_one({"name": "Asha", "age": 25})        # blocking insert
print(col.find_one({"age": {"$gt": 20}}, {"_id": 0}))   # {'name': 'Asha', 'age': 25}
```
```javascript
// JavaScript way — every call is a Promise
const col = client.db("shop").collection("users");
await col.insertOne({ name: "Asha", age: 25 });
console.log(await col.findOne({ age: { $gt: 20 } }, { projection: { _id: 0 } }));
```

Key difference: query syntax is identical (it is MongoDB's own), but PyMongo blocks while waiting, so in FastAPI use plain `def` endpoints. Python dicts keep insertion order, and `ObjectId` is a special type that must be converted with `str()` for JSON.

## 🟠 FastAPI Connection
With PyMongo in FastAPI use plain `def` endpoints so FastAPI runs them in the thread pool. Create ONE `MongoClient` for the whole app (it is thread-safe and pools connections). `ObjectId` is not JSON serialisable, so convert `_id` to a string, and validate path ids with `ObjectId(...)` inside try/except. For async endpoints use Motor or the new PyMongo Async API.

```python
# FastAPI + PyMongo (sync): endpoints are plain def so they run in the thread pool
from bson import ObjectId                         # id type
from bson.errors import InvalidId                 # bad id string
from fastapi import FastAPI, HTTPException        # web
from fastapi.testclient import TestClient         # demo client
from pymongo import MongoClient                   # sync driver

client_db = MongoClient("mongodb://127.0.0.1:34201", serverSelectionTimeoutMS=3000)   # ONE client per process
col = client_db["shop_demo"]["fa_pymongo"]        # collection
col.drop()
app = FastAPI()


def oid(s: str) -> ObjectId:
    try:
        return ObjectId(s)                        # validate path param
    except InvalidId:
        raise HTTPException(422, "invalid id")


@app.post("/items", status_code=201)
def create(name: str, price: float) -> dict[str, str]:
    return {"id": str(col.insert_one({"name": name, "price": price}).inserted_id)}   # ObjectId -> str (not JSON serialisable)


@app.get("/items/{item_id}")
def read(item_id: str) -> dict[str, object]:
    doc = col.find_one({"_id": oid(item_id)})
    if doc is None:
        raise HTTPException(404, "not found")
    doc["id"] = str(doc.pop("_id"))               # replace _id with a string id
    return doc


c = TestClient(app)
new = c.post("/items", params={"name": "pen", "price": 5}).json()
print(sorted(new))                                # ['id']
print(c.get(f"/items/{new['id']}").json()["name"])
print(c.get("/items/zzz").status_code, c.get(f"/items/{ObjectId()}").status_code)
client_db.close()

# Output:
# ['id']
# pen
# 422 404
```

## ⚠️ Common Mistakes to Avoid

❌ Mistake 1: Creating a new `MongoClient` per request
✅ Correct: one global client; it already pools connections

```python
from pymongo import MongoClient
# Wrong — opens new sockets and a monitoring thread on every call
def handler():
    c = MongoClient("mongodb://127.0.0.1:34201")
    return c.shop_demo.users.count_documents({})
# Right — create once at import / startup
client = MongoClient("mongodb://127.0.0.1:34201")
def handler2():
    return client.shop_demo.users.count_documents({})
```

❌ Mistake 2: Expecting `insert_one` NOT to change your dict, and re-inserting it
✅ Correct: pass a copy, or build a new dict each time

```python
from pymongo import MongoClient
from pymongo.errors import DuplicateKeyError
col = MongoClient("mongodb://127.0.0.1:34201").shop_demo.m2; col.drop()
doc = {"name": "A"}
col.insert_one(doc)
print("_id" in doc)                   # True  <- the driver added _id to YOUR dict
try:
    col.insert_one(doc)               # Wrong — same _id again
except DuplicateKeyError:
    print("duplicate _id")
col.insert_one({"name": "A"})         # Right — a fresh dict gets a fresh _id
```

❌ Mistake 3: Treating `find()` as a list, or replacing a doc when you meant to update a field
✅ Correct: `list(cursor)`; use `$set` for partial updates

```python
cur = col.find({})
print(type(cur).__name__)             # Cursor (lazy, one-time iterable)
# Wrong — replaces the whole document, other fields are lost
col.replace_one({"name": "A"}, {"y": 1})
print(col.find_one({"y": 1}, {"_id": 0}))                    # {'y': 1}  (name is gone)
# Right — only change one field
col.update_one({"y": 1}, {"$set": {"name": "A"}})
```

## 🧠 Tricky Interview Question

```python
# What will this output?
from pymongo import MongoClient
col = MongoClient("mongodb://127.0.0.1:34201").shop_demo.t1
col.drop()
d = {"name": "A"}
col.insert_one(d)
print("_id" in d)
print(col.update_one({"name": "A"}, {"$set": {"name": "A"}}).modified_count)
col.update_one({"name": "Z"}, {"$set": {"x": 1}}, upsert=True)
print(col.count_documents({}))
print(col.find_one({"name": "nobody"}))
```
Answer: `True`, `0`, `2`, `None`. `insert_one` mutates the dict you pass by adding `_id`. `update_one` that sets the same value reports `modified_count == 0` even though `matched_count == 1`. `upsert=True` creates a new document when nothing matches, so the count becomes 2. `find_one` with no match returns `None`, it does not raise. Verified against a local MongoDB.

## ⚫ Interview Questions + Answers

Q1: What is `ObjectId`?
A1: A 12-byte unique id: 4-byte timestamp, 5-byte random value, 3-byte counter. It is the default `_id`. It sorts roughly by creation time and `ObjectId.generation_time` gives the creation time. Convert with `str()` and `ObjectId(str)`.

Q2: When do you embed and when do you reference?
A2: Embed data that is read together and bounded in size (address, order lines). Reference (store another `_id`) for data that is shared, large or grows without limit (all comments of a viral post). There are no joins by default, so choose by access pattern; `$lookup` exists but is slower.

Q3: Why create indexes?
A3: Without an index every query scans the whole collection. `create_index([("email", 1)], unique=True)` makes lookups O(log n) and enforces uniqueness. Check plans with `.explain()`.

Q4: Is a single-document write atomic?
A4: Yes, writes to one document are atomic, including nested fields. Multi-document transactions need a replica set (`with client.start_session() as s: s.with_transaction(...)`).

Q5: PyMongo vs Motor?
A5: PyMongo is blocking. Motor (and the newer PyMongo Async API in 4.9+) is for asyncio, with `await` on each call. The query syntax is the same.

## 🔷 When to Use + When Not to Use
✅ Use when:
- Data is document-shaped, nested or changes shape often
- Event logs, catalogs, user profiles, content stores
- You want a simple sync driver for scripts, Celery workers, Flask/Django, or FastAPI `def` endpoints

❌ Avoid when:
- Data is strongly relational with many joins and strict integrity (use PostgreSQL)
- You are inside `async def` endpoints (blocks the loop) - use Motor / PyMongo Async
- You need complex multi-row transactions everywhere

## ⚡ 3-Line Summary
English: PyMongo talks to MongoDB with plain dicts: `insert_one`, `find`, `update_one` with `$set`, and `aggregate`. Keep one global client, add indexes, convert `ObjectId` to string for JSON, and use plain `def` endpoints in FastAPI.
