# 043. zip()
# हिंदी में: zip() (कई sequences को साथ-साथ चलाना)

---

## 🔵 Simple Definition (English)
`zip(a, b, c)` takes several iterables and yields tuples that combine the items at the same position: `(a[0], b[0], c[0])`, then `(a[1], b[1], c[1])`, and so on. Like a zipper on a jacket, it joins two sides tooth by tooth. It stops at the shortest input unless you pass `strict=True`.

## 🔵 सरल परिभाषा (Hindi)
`zip(a, b, c)` कई iterables लेता है और एक ही position के items को जोड़कर tuples देता है: `(a[0], b[0], c[0])`, फिर `(a[1], b[1], c[1])`। जैसे jacket की zip दाँत-दाँत जोड़ती है। यह सबसे छोटे input पर रुक जाता है, जब तक आप `strict=True` न दें।

---

## 🔴 Problem it Solves
Data often arrives in parallel lists: `names`, `ages`, `cities`. To process them together you would write `for i in range(len(names))` and index each list, which is clumsy and error-prone. `zip` pairs them cleanly, builds dicts from two lists, and can even transpose matrices.

## 🔴 यह क्यों बना? (Hindi)
Data अक्सर parallel lists में आता है: `names`, `ages`, `cities`। इन्हें साथ चलाने के लिए `range(len(names))` से हर list को index करना पड़ता था, जो भद्दा और गलती-प्रवण है। `zip` इन्हें साफ़ तरीके से जोड़ता है, दो lists से dict बनाता है, और matrix transpose भी करता है।

---

## 🟢 How it Works — Step by Step

```
Step 1 → zip(a, b) creates a lazy zip iterator
Step 2 → Each next() calls next() on every input iterator
Step 3 → It returns one tuple: (item_from_a, item_from_b)
Step 4 → If ANY input is exhausted → zip stops (shortest wins)
Step 5 → strict=True raises ValueError if lengths differ (Python 3.10+)
```

## 🟢 कैसे काम करता है? (Hindi)
```
Step 1 → zip एक lazy iterator बनाता है
Step 2 → हर next() पर सभी inputs से एक-एक item लिया जाता है
Step 3 → उनका tuple बनता है
Step 4 → कोई भी input खत्म हुआ तो zip रुक जाता है
Step 5 → strict=True हो तो लंबाई अलग होने पर ValueError
```

## 🟡 Real World Example
Swiggy stores `restaurant_names` and `ratings` as two lists from different queries; `zip` merges them to print "Biryani House - 4.5". In ML, `zip(features, labels)` pairs each input with its target; in an AI app `zip(texts, embeddings)` attaches every vector to its source text before saving to a vector DB.

## 🟡 Real Example Hindi mein
Swiggy में `restaurant_names` और `ratings` दो अलग queries से आती हैं; `zip` उन्हें जोड़कर "Biryani House - 4.5" बनाता है। ML में `zip(features, labels)` हर input को उसके target से जोड़ता है; AI app में `zip(texts, embeddings)` vector DB में रखने से पहले हर vector को उसके text से जोड़ता है।

## 💻 Code Example — Basic
```python
# Basic zip examples - every line commented
from typing import Dict, List  # type hints

names: List[str] = ["Asha", "Ravi", "Meera"]  # first list
ages: List[int] = [25, 30, 28]  # second list, same length

for name, age in zip(names, ages):  # unpack each pair
    print(name, age)  # use both values
# Output:
# Asha 25
# Ravi 30
# Meera 28

print(list(zip(names, ages)))  # see the raw tuples
# Output: [('Asha', 25), ('Ravi', 30), ('Meera', 28)]

people: Dict[str, int] = dict(zip(names, ages))  # two lists -> one dict
print(people)  # Output: {'Asha': 25, 'Ravi': 30, 'Meera': 28}

# Shortest input wins
print(list(zip([1, 2, 3], ["a", "b"])))  # 3 vs 2 items
# Output: [(1, 'a'), (2, 'b')]

# Three or more inputs
cities: List[str] = ["Pune", "Delhi", "Goa"]  # third list
print(list(zip(names, ages, cities)))  # triples
# Output: [('Asha', 25, 'Pune'), ('Ravi', 30, 'Delhi'), ('Meera', 28, 'Goa')]

# Unzip with * (star operator)
pairs = [(1, "a"), (2, "b"), (3, "c")]  # list of pairs
nums, letters = zip(*pairs)  # * spreads pairs as separate arguments
print(nums, letters)  # results are tuples
# Output: (1, 2, 3) ('a', 'b', 'c')
```

## 💻 Code Example — Advanced
```python
# Production style: strict mode, zip_longest, transpose, sliding pairs, batching
from itertools import zip_longest  # pad shorter inputs instead of cutting
from typing import List, Tuple  # type hints

# 1. strict=True catches silent data loss (Python 3.10+)
texts: List[str] = ["hello", "world", "extra"]  # 3 texts
vectors: List[List[float]] = [[0.1], [0.2]]  # only 2 embeddings (bug!)
try:  # guard the strict zip
    for t, v in zip(texts, vectors, strict=True):  # lengths must match
        pass  # nothing to do, the error is the point
except ValueError as exc:  # raised on mismatch
    print("ValueError:", exc)  # explain
# Output: ValueError: zip() argument 2 is shorter than argument 1

# 2. zip_longest pads the shorter side
print(list(zip_longest([1, 2, 3], ["a"], fillvalue="-")))  # fill missing with '-'
# Output: [(1, 'a'), (2, '-'), (3, '-')]

# 3. Transpose a matrix (rows <-> columns)
matrix: List[List[int]] = [[1, 2, 3], [4, 5, 6]]  # 2 rows x 3 columns
transposed: List[Tuple[int, ...]] = list(zip(*matrix))  # 3 rows x 2 columns
print(transposed)  # Output: [(1, 4), (2, 5), (3, 6)]

# 4. Compare neighbours: zip(x, x[1:])
prices: List[int] = [100, 120, 90, 150]  # daily prices
changes: List[int] = [b - a for a, b in zip(prices, prices[1:])]  # day-to-day change
print(changes)  # Output: [20, -30, 60]

# 5. Zip is lazy and single-use
z = zip([1, 2], [3, 4])  # create a zip iterator
print(list(z), list(z))  # second pass is empty
# Output: [(1, 3), (2, 4)] []

# 6. Batch an iterable into groups of 2 using one shared iterator
it = iter([1, 2, 3, 4, 5, 6])  # single iterator object
print(list(zip(it, it)))  # both arguments pull from the same iterator
# Output: [(1, 2), (3, 4), (5, 6)]

# 7. Parallel sort: sort names by score
names: List[str] = ["Asha", "Ravi", "Meera"]  # names
scores: List[int] = [70, 95, 82]  # their scores
ranked = [n for _, n in sorted(zip(scores, names), reverse=True)]  # sort pairs by score
print(ranked)  # Output: ['Ravi', 'Meera', 'Asha']
```

## 🟠 JavaScript vs Python Comparison

```python
# Python
names = ["Asha", "Ravi"]
ages = [25, 30]
for n, a in zip(names, ages):
    print(n, a)
d = dict(zip(names, ages))     # {'Asha': 25, 'Ravi': 30}
```

```javascript
// JavaScript (no built-in zip)
const names = ["Asha", "Ravi"];
const ages = [25, 30];
names.forEach((n, i) => console.log(n, ages[i]));       // index into 2nd array
const zipped = names.map((n, i) => [n, ages[i]]);       // manual zip
const d = Object.fromEntries(zipped);                   // {Asha: 25, Ravi: 30}
// lodash: _.zip(names, ages)
```

Key differences: JavaScript has no native `zip`; you `map` with an index and risk `undefined` when lengths differ. Python's `zip` is lazy, works with any iterables, stops at the shortest, and offers `strict=True`.

## 🟠 FastAPI Connection
FastAPI services use `zip` to join parallel results: model scores with labels, database ids with computed values, or a list of embeddings with the original texts before returning a JSON response.

```python
# FastAPI: pair labels with predicted scores (needs: pip install fastapi)
from typing import Dict, List  # type hints
from fastapi import FastAPI  # the framework

app: FastAPI = FastAPI()  # create app
LABELS: List[str] = ["spam", "promo", "personal"]  # fixed classes


@app.post("/classify")  # POST /classify with a list of scores
def classify(scores: List[float]) -> Dict[str, float]:
    # strict=True: a wrong number of scores becomes a loud error, not silent truncation
    return dict(zip(LABELS, scores, strict=True))  # {"spam": 0.7, ...}
```

## ⚠️ Common Mistakes to Avoid

❌ Mistake 1: Silent data loss with unequal lengths
```python
a = [1, 2, 3]
b = ["x", "y"]

# Wrong - third item disappears with no warning:
print(list(zip(a, b)))              # [(1, 'x'), (2, 'y')]

# Correct - fail loudly, or pad:
# list(zip(a, b, strict=True))      # ValueError
from itertools import zip_longest
print(list(zip_longest(a, b)))      # [(1, 'x'), (2, 'y'), (3, None)]
```

❌ Mistake 2: Reusing a consumed zip
```python
z = zip([1, 2], [3, 4])
print(list(z))     # [(1, 3), (2, 4)]
print(list(z))     # []  - already used up!

# Correct: store the result once
pairs = list(zip([1, 2], [3, 4]))
```

❌ Mistake 3: Expecting a list (indexing or len)
```python
z = zip([1, 2], [3, 4])
# z[0]       -> TypeError: 'zip' object is not subscriptable
# len(z)     -> TypeError: object of type 'zip' has no len()

# Correct:
pairs = list(zip([1, 2], [3, 4]))
print(pairs[0], len(pairs))   # (1, 3) 2
```

## 🧠 Tricky Interview Question

**Q**: What does this print?

```python
a = iter([1, 2, 3])
b = iter("ab")
print(list(zip(a, b)))
print(next(a))
```

**Answer**: It prints `[(1, 'a'), (2, 'b')]` and then `next(a)` raises `StopIteration`. In round 3, zip pulled `3` from `a` first, then found `b` exhausted and stopped. The `3` was already consumed and is lost, so `a` is empty. Lesson: with iterators the argument order matters; put the shortest first, or use `strict=True`.

## ⚫ Interview Questions + Answers

Q1: What happens when the iterables have different lengths?
A1: `zip` stops at the shortest and ignores the rest. Use `strict=True` (3.10+) to raise `ValueError`, or `itertools.zip_longest` to pad with a `fillvalue`.

Q2: How do you "unzip"?
A2: `a, b = zip(*pairs)`. The `*` unpacks the list of pairs into separate arguments; `zip` then regroups them by position. The results are tuples.

Q3: Is `zip` returning a list?
A3: No. Since Python 3 it returns a lazy, single-use iterator. Wrap with `list()` to materialise. Python 2 returned a list.

Q4: How can you build a dict from two lists?
A4: `dict(zip(keys, values))`. If keys repeat, later values overwrite earlier ones.

Q5: How do you compare each item with the next one?
A5: `zip(items, items[1:])` yields `(items[0], items[1])`, `(items[1], items[2])`, ... Or `itertools.pairwise(items)` in Python 3.10+.

## 🔷 When to Use + When Not to Use

✅ Use when:
- Parallel lists need to be processed together
- Building dicts from keys and values
- Transposing matrices or comparing neighbours

❌ Avoid when:
- Lengths may differ and you cannot tolerate data loss (use `strict=True`)
- You also need the index (combine with `enumerate`)
- Data is tabular and large (use pandas/NumPy instead)

English: `zip` pairs items from several iterables by position and stops at the shortest. It is lazy and single-use; use `strict=True` to avoid silent truncation. `zip(*x)` unzips or transposes data.
