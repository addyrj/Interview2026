# 339. Beanie (MongoDB ODM)
# हिंदी में: Beanie (MongoDB के लिए Async ODM)

---

## 🔵 Simple Definition (English)
Beanie is an async Object-Document Mapper (ODM) for MongoDB built on Pydantic and the PyMongo async driver. Your document classes are Pydantic models, so you get validation, type hints and automatic JSON schema, while queries are written in Python (`Customer.find(Customer.age > 20)`).

## 🔵 सरल परिभाषा (Hindi)
Beanie MongoDB के लिए async Object-Document Mapper (ODM) है जो Pydantic और PyMongo के async driver पर बना है। आपकी document classes Pydantic models होती हैं, इसलिए validation, type hints और JSON schema अपने आप मिलते हैं, और queries Python में लिखी जाती हैं (`Customer.find(Customer.age > 20)`)।

---

## 🔴 Problem it Solves
Using raw PyMongo means building dictionaries by hand, no validation, and strings everywhere (`{"$set": {...}}`, `"address.city"`). Typos only fail at runtime and results are untyped dicts. Beanie validates data when you save and load, gives typed field expressions, manages indexes declaratively, and fits FastAPI's Pydantic world, so the same class can be both DB model and API model.

## 🔴 यह क्यों बना? (Hindi)
सीधे PyMongo में dictionaries हाथ से बनानी पड़ती हैं, validation नहीं होता, और हर जगह strings होती हैं (`{"$set": {...}}`, `"address.city"`)। Typos सिर्फ runtime पर पकड़ में आते हैं और results untyped dicts होते हैं। Beanie save और load पर data validate करता है, typed field expressions देता है, indexes declaratively संभालता है, और FastAPI की Pydantic दुनिया में फिट बैठता है, इसलिए वही class DB model और API model दोनों हो सकती है।

## 🟢 How it Works — Step by Step

```
Step 1 → pip install beanie  (it brings pymongo with the async client)
Step 2 → class Customer(Document): fields are Pydantic fields
Step 3 → Optional inner class Settings: collection name, indexes
Step 4 → client = AsyncMongoClient("mongodb://...")
Step 5 → await init_beanie(database=client["db"], document_models=[Customer])
Step 6 → init_beanie creates declared indexes and wires models to collections
Step 7 → await Customer(...).insert(); await Customer.find(...).to_list()
Step 8 → Mongo stores BSON; Beanie turns it back into validated Python objects
```

## 🟡 Real World Example
A food-delivery or CRM backend stores customers with flexible nested data: addresses, preferences, order history summaries. A unique index on email prevents duplicate signups, a `created_at` timestamp is generated by default, and a nightly aggregation computes the average age or spend. Beanie keeps all of this typed and async.

## 🟡 Real Example Hindi mein
Food-delivery या CRM backend customers को लचीले nested data के साथ रखता है: addresses, preferences, order history summaries। Email पर unique index duplicate signup रोकता है, `created_at` timestamp default से बनता है, और रात की aggregation औसत उम्र या खर्च निकालती है। Beanie यह सब typed और async रखता है।

## 💻 Code Example — Basic
```python
# Basic: Document, Indexed unique field, nested model, find, update, duplicate error, aggregate
# Verified against a local mongod (my own instance), beanie 2.2, pymongo 4.19
import asyncio                                                    # run the coroutine
from datetime import datetime, timezone                           # timestamps
from typing import Annotated, Optional                            # Indexed uses Annotated in Beanie 2
from beanie import Document, Indexed, init_beanie                 # core Beanie API
from pymongo import AsyncMongoClient                              # async client (replaces Motor)
from pydantic import BaseModel, Field                             # nested model + field rules


class Address(BaseModel):                                         # embedded document (no collection)
    city: str                                                     # city name
    pin: str                                                      # postal code


class Customer(Document):                                         # a collection of documents
    email: Annotated[str, Indexed(unique=True)]                   # unique index on email
    name: str                                                     # required string
    age: int = Field(ge=0)                                        # validated: must be >= 0
    address: Optional[Address] = None                             # nested object or None
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))   # default value

    class Settings:                                               # Beanie config
        name = "customers"                                        # collection name


async def main() -> None:                                         # async entry point
    client = AsyncMongoClient("mongodb://127.0.0.1:27017")        # connect (use your own URL / env var)
    await client.drop_database("demo_beanie")                     # start clean for the demo
    await init_beanie(database=client["demo_beanie"], document_models=[Customer])   # register + indexes
    c = await Customer(email="a@x.com", name="Asha", age=28,
                       address=Address(city="Pune", pin="411001")).insert()   # INSERT one document
    await Customer(email="b@x.com", name="Bob", age=40).insert()  # another one
    print(type(c.id).__name__)                                    # id is a PydanticObjectId
    found = await Customer.find_one(Customer.email == "a@x.com")  # typed expression, not a dict
    print(found.name, found.address.city)                         # nested access works
    print([x.name async for x in Customer.find(Customer.age > 20).sort("-age")])   # async iteration
    await Customer.find_one(Customer.email == "b@x.com").update({"$set": {"age": 41}})   # Mongo operator
    print((await Customer.find_one(Customer.name == "Bob")).age)  # updated value
    try:                                                          # duplicate email
        await Customer(email="a@x.com", name="Dup", age=1).insert()   # unique index violated
    except Exception as e:                                        # pymongo error
        print(type(e).__name__)                                   # DuplicateKeyError
    print(await Customer.find(Customer.age >= 0).count())         # how many documents
    res = await Customer.aggregate([{"$group": {"_id": None, "avg": {"$avg": "$age"}}}]).to_list()   # pipeline
    print(res)                                                    # average age
    await client.close()                                          # close connections


asyncio.run(main())                                               # run it

# Output (verified):
# PydanticObjectId
# Asha Pune
# ['Bob', 'Asha']
# 41
# DuplicateKeyError
# 2
# [{'_id': None, 'avg': 34.5}]
```

## 💻 Code Example — Advanced
```python
# Production style: FastAPI + Beanie in lifespan, response_model=Document, id validation (verified)
from contextlib import asynccontextmanager                        # lifespan helper
from collections.abc import AsyncIterator                         # lifespan type
from beanie import Document, PydanticObjectId, init_beanie        # Beanie pieces
from fastapi import FastAPI, HTTPException                        # FastAPI
from fastapi.testclient import TestClient                         # test client
from pydantic import BaseModel                                    # request schema
from pymongo import AsyncMongoClient                              # async client


class Note(Document):                                             # the stored document
    text: str                                                     # note body
    tags: list[str] = []                                          # list of tags

    class Settings:                                               # config
        name = "notes"                                            # collection


class NoteIn(BaseModel):                                          # request body (no id)
    text: str                                                     # required
    tags: list[str] = []                                          # optional


@asynccontextmanager                                              # startup + shutdown
async def lifespan(app: FastAPI) -> AsyncIterator[None]:          # FastAPI lifespan
    client = AsyncMongoClient("mongodb://127.0.0.1:27017")        # prod: read from env / settings
    await init_beanie(database=client["demo_notes"], document_models=[Note])   # register models
    yield                                                         # app runs
    await client.close()                                          # close on shutdown


app: FastAPI = FastAPI(lifespan=lifespan)                         # create app


@app.post("/notes", response_model=Note, status_code=201)         # create
async def create(body: NoteIn) -> Note:                           # Document used as response model
    return await Note(**body.model_dump()).insert()               # insert and return it


@app.get("/notes/{note_id}", response_model=Note)                 # read one
async def read(note_id: PydanticObjectId) -> Note:                # invalid ids => automatic 422
    note = await Note.get(note_id)                                # find by _id
    if note is None:                                              # not found
        raise HTTPException(404, "note not found")                # 404
    return note                                                   # serialized by Pydantic


@app.get("/notes", response_model=list[Note])                     # search
async def search(tag: str | None = None) -> list[Note]:           # optional filter
    q = Note.find(Note.tags == tag) if tag else Note.find_all()   # matches array element
    return await q.to_list()                                      # run the query


with TestClient(app) as c:                                        # runs lifespan
    r = c.post("/notes", json={"text": "hi", "tags": ["py"]}).json()   # create
    print(sorted(r.keys()), r["text"])                            # note: key is "_id", not "id"
    print(c.get(f"/notes/{r['_id']}").json()["tags"])             # read back
    print(c.get("/notes/65f1a2b3c4d5e6f7a8b9c0d1").status_code)   # valid-looking id, not stored
    print(len(c.get("/notes", params={"tag": "py"}).json()))      # search by tag
    print(c.get("/notes/not-an-id").status_code)                  # bad id

# Output (verified):
# ['_id', 'tags', 'text'] hi
# ['py']
# 404
# 1
# 422
```
Requires a running MongoDB. (Verified against a temporary local mongod; for tests you can also use `mongomock-motor`-style fakes or a Docker `mongo` container.)

## 🟠 JavaScript vs Python Comparison

| Concept | Beanie | JavaScript (Mongoose) |
|---------|--------|-----------------------|
| Schema | Pydantic class | `new Schema({...})` |
| Validation | Pydantic (types, `Field(ge=0)`) | Schema validators |
| Insert | `await Doc(...).insert()` | `await new Model({...}).save()` |
| Query | `Doc.find(Doc.age > 20)` | `Model.find({ age: { $gt: 20 } })` |
| Unique index | `Indexed(unique=True)` | `unique: true` |

```python
# Python way
adults = await Customer.find(Customer.age > 20).sort("-age").to_list()   # typed expression
```
```javascript
// JavaScript way (Mongoose)
const adults = await Customer.find({ age: { $gt: 20 } }).sort("-age");   // plain object filter
```

Key difference: Mongoose filters are plain objects with operators like `$gt`; Beanie lets you write normal Python operators on typed fields, so editors can autocomplete and catch typos.

## 🟠 FastAPI Connection
Beanie is built for FastAPI: a `Document` is a Pydantic model, so it works directly as `response_model`. Initialize in `lifespan`, validate ids with `PydanticObjectId` as a path parameter (bad ids become 422 automatically), and keep separate input models (`NoteIn`) so clients cannot send `_id`. Note: `response_model=Note` serializes the id under its alias `_id` by default.

```python
# FastAPI example — partial update with Beanie
from fastapi import HTTPException                                 # error

@app.patch("/notes/{note_id}", response_model=Note)               # PATCH
async def patch(note_id: PydanticObjectId, body: NoteIn) -> Note:
    note = await Note.get(note_id)                                # load document
    if note is None:                                              # missing
        raise HTTPException(404, "note not found")                # 404
    await note.set({Note.text: body.text})                        # atomic $set of one field
    return note                                                   # return updated note
```

## ⚠️ Common Mistakes to Avoid

❌ Mistake 1: Forgetting `init_beanie` (or forgetting to list a model in `document_models`)
✅ Correct: initialize once at startup with ALL document models

```python
# Wrong — CollectionWasNotInitialized
note = await Note(text="x").insert()
# Right
await init_beanie(database=client["db"], document_models=[Note, User])
```

❌ Mistake 2: Using the old Motor client with the new Beanie
✅ Correct: Beanie 2.x uses PyMongo's `AsyncMongoClient`. Match the Beanie version with the client it expects (older Beanie 1.x used `motor.motor_asyncio.AsyncIOMotorClient`).

```python
# Wrong for Beanie 2.x
from motor.motor_asyncio import AsyncIOMotorClient
# Right
from pymongo import AsyncMongoClient
```

❌ Mistake 3: Expecting `id` in the JSON response
✅ Correct: Mongo's field is `_id` (alias of `id`). Use a separate response schema if the client expects `id`

```python
# Wrong — KeyError: 'id'
r = client.post("/notes", json={...}).json()
r["id"]
# Right — either read r["_id"] or define NoteOut(BaseModel) with id: PydanticObjectId
```

## 🧠 Tricky Interview Question

```python
# Will this work?  Customer has a unique index on email
await Customer(email="a@x.com", name="A", age=1).insert()
await Customer(email="a@x.com", name="B", age=2).insert()
```
Answer: The second insert raises `pymongo.errors.DuplicateKeyError`. Beanie created the unique index at `init_beanie` time, and MongoDB enforces it on the server. Important nuance: if `init_beanie` was never called, or if the index could not be built because duplicates already existed in the collection, the unique rule is not enforced. Always handle `DuplicateKeyError` and return a 409.

## ⚫ Interview Questions + Answers

Q1: What is an ODM and how is it different from an ORM?
A1: ODM maps classes to documents (MongoDB) instead of table rows. There are no joins or fixed schema; relations are embedded documents or references (`Link`). The mapping idea is the same.

Q2: Why does Beanie use Pydantic?
A2: Pydantic provides validation, type coercion, serialization and JSON schema for free, and FastAPI already uses Pydantic, so models are reusable across the DB and API layers.

Q3: How do you handle relations in Beanie?
A3: Either embed sub-documents (best for data read together) or use `Link[OtherDoc]` references with `fetch_links=True`, which uses `$lookup`. Embedding avoids joins and is the MongoDB way.

Q4: How do you create indexes?
A4: Use `Annotated[str, Indexed(unique=True)]` on fields, or `Settings.indexes = [...]` with `pymongo.IndexModel` for compound indexes. `init_beanie` creates them at startup.

Q5: Do Mongo writes support transactions?
A5: Yes on replica sets or sharded clusters: `async with await client.start_session() as s: async with s.start_transaction(): await doc.insert(session=s)`. A standalone mongod does not support multi-document transactions.

## 🔷 When to Use + When Not to Use
✅ Use when:
- Document-shaped, flexible data (profiles, catalogs, logs, content)
- FastAPI service with MongoDB where you want Pydantic validation
- You need fast iteration without migrations

❌ Avoid when:
- Strongly relational data with many joins and strict integrity (use PostgreSQL + SQLAlchemy)
- Heavy multi-document transactions are core to the domain (payments ledger)
- Your team has no MongoDB experience and no real need for documents
