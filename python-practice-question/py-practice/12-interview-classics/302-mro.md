# Q302. MRO (Method Resolution Order)
# Category: Interview Classics
# Difficulty: ⭐⭐ Medium

---

## ❓ Question
What is the MRO? What does the following print, and how does Python decide the order?

```python
class A: ...
class B(A): ...
class C(A): ...
class D(B, C): ...
```

---

## 💡 Quick Concept (2 lines only)
MRO is the order in which Python searches base classes for an attribute or method; it uses C3 linearization (children before parents, left to right).
हिंदी: MRO बताता है कि method किस क्रम में class hierarchy में खोजी जाएगी — C3 algorithm से।

---

## ✅ Answer / Solution

```python
# ============================================
# SOLUTION
# ============================================
class A:  # Step 1: root of the diamond
    def hello(self) -> str:
        return "A"  # base implementation


class B(A):  # Step 2: left branch
    def hello(self) -> str:
        return "B>" + super().hello()  # delegate to next in MRO


class C(A):  # Step 3: right branch
    def hello(self) -> str:
        return "C>" + super().hello()  # delegate to next in MRO


class D(B, C):  # Step 4: diamond bottom
    def hello(self) -> str:
        return "D>" + super().hello()  # next in MRO is B


# ============================================
# TEST CASES
# ============================================
print([k.__name__ for k in D.__mro__])  # Expected: ['D', 'B', 'C', 'A', 'object']
print(D().hello())  # Expected: D>B>C>A  (A is called once, after both B and C)
print(D.mro() == list(D.__mro__))  # Expected: True
```

Impossible order: listing a base before its own subclass fails.

```python
try:
    class A: ...  # base
    class B(A): ...  # child of A
    class X(A, B): ...  # A before B is inconsistent
except TypeError as e:
    print(e)  # Expected: Cannot create a consistent method resolution order (MRO) for bases A, B
```

---

## 🔍 Why This Works (3 lines max)
C3 merges the parents' linearizations so a class always comes before its bases and the order of the base list is respected. `super()` follows the MRO of the instance's class, not the class where it is written, so each class runs exactly once.
हिंदी: `super()` अगली class को MRO से चुनता है, सीधे parent से नहीं — इसलिए A सिर्फ एक बार चलता है।

## ⚡ Alternative Solution
```python
class Base:  # cooperative multiple inheritance
    def __init__(self, **kw) -> None:
        print("Base")  # end of the chain


class Left(Base):
    def __init__(self, **kw) -> None:
        print("Left")  # runs
        super().__init__(**kw)  # pass to next in MRO


class Right(Base):
    def __init__(self, **kw) -> None:
        print("Right")  # runs
        super().__init__(**kw)  # pass to next in MRO


class Child(Left, Right):
    pass


Child()  # Expected prints: Left, Right, Base (one per line)
```

---

## ⚠️ Common Mistake
```python
# ❌ Wrong: calling parents explicitly in a diamond -> Base runs twice
class P:
    def __init__(self) -> None:
        print("P init")

class Q(P):
    def __init__(self) -> None:
        P.__init__(self)  # hard-coded parent call

class R(P):
    def __init__(self) -> None:
        P.__init__(self)  # hard-coded parent call

class S(Q, R):
    def __init__(self) -> None:
        Q.__init__(self)  # runs P init
        R.__init__(self)  # runs P init again

S()  # prints "P init" twice

# ✅ Correct: use super() everywhere so the MRO runs each class once
```
